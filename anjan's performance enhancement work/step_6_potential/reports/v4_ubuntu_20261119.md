## What V4 changes

`solvers/optimised_laplace_v4.py` retains V3's kernel and wrapper arithmetic, private shrinking halos, exact unsigned maximum-error reduction, float64 operation order, fixed faces and first-converged-state prefix replay. It changes only the desktop tuning constants and runtime identity/profile metadata. Temporal batches still stop at the existing progress boundaries, so each logged iteration/error retains its original meaning. `NUMBA_NUM_THREADS` overrides the default, as with V2/V3.

This is a measured tuning profile, not a new mathematical algorithm, online autotuning or a proof of a global optimum. It does not require AVX-512 on another CPU; Numba compiles for its host, but performance elsewhere is unestablished. No thread pinning, compiler fast-math, reduced precision, relaxed tolerance or changed input was introduced. The runner adds `--implementation optimised-v4`; all earlier selectors remain available.

### Numerical verification

For **each of the six new runs**, `compare_desktop_runs.py` independently rehashed the saved outputs from disk and compared array bits to the original Ubuntu run `20261116_103848_750500`. All nine files are byte-identical. All 81,270,000 saved float64 values per run are finite and bit-identical: maximum absolute difference zero. Shapes, data types, total output size and every original source/input hash match.

All **340 logged iteration/max-change pairs** match the original exactly. Every new run records zero-based stopping label **16975**, **16976 logical global updates**, and final maximum change **0.0009999202787085437**. The old original report did not retain that precise final-update error; its directly compared evidence is the saved fields and logged samples, not an unsaved scalar potential or unsaved final-error value. V4 also records speculative/replayed work explicitly, as V3 does.

Ten small-fixture tests cover unchanged inputs, bitwise field equality, iteration-limit boundaries around batch/logging events, nonfinite/overflow/subnormal/signed-zero behaviour, layout/float32 fallbacks, irregular private tiles at depths through eight, exact intermediate error reductions, first-converged-state replay, default/explicit worker counts, runner selection and byte-identical three-/nine-output workflows. V4's temporal kernel AST is identical to V3's; the differences are tuning constants and runtime profile metadata.

### Measurement limits

These are three full-run trials per candidate, not a proof of a global hardware optimum. The selected short-workload profiles are close, so another day or background load can change their ordering. The historical original is a single run on the same desktop, on an earlier day. Ordinary desktop activity, thermals and clocks were not controlled. No other observation solver was running during the timed full trials. An isolated, sub-second cached-assembly-inspection probe occurred during the first V3 trial; no instruction-level conclusion was drawn from the cached inspection, and the three V3 timings agree within approximately 1.1%.

 Each invocation includes startup/JIT, logging, the solve, gradients/scaling, all interpolation and all nine saves. Input copying and post-run verification/hashing are outside timing. V3 uses four workers to reproduce the laptop-tuned configuration; V4 uses sixteen. CPU seconds sum activity across workers and are not elapsed seconds. Linux GNU time supplies largest-process peak RSS and CPU time; sampled tree counters remain in each report.

## Reproduce

From `step_6_potential/`, with the existing environment activated:

```bash
python -m pip install -r requirements-optimised.txt
NUMBA_NUM_THREADS=16 python measure_potential.py --input-dir "../step_4_package/runs/20261113_160555_320989" --implementation optimised-v4 --max-seconds 0 --label ubuntu_v4_full_step
```

The same command without `NUMBA_NUM_THREADS=16` uses V4's default of up to sixteen workers. An existing environment override takes precedence. Omit `--first-field-only` to preserve the nine-file Ubuntu comparison workload.

Repeated paired comparison against the saved original:

```bash
python benchmarks/compare_desktop_runs.py --input-dir "../step_4_package/runs/20261113_160555_320989" --reference-run "runs/20261116_103848_750500" --output "runs/v4_full_comparison.json" --trials 3
```

Small-fixture validation:

```bash
python -m unittest discover -s tests -p test_implementations.py -v
```
