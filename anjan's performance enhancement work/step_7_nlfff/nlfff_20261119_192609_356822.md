### Material measurement limitations

This laptop has 7.35 GiB OS-visible RAM. Available RAM before preparation was approximately 1.36 GiB and fell to about 50 MiB during the trial. A later snapshot recorded 499.39 MiB available and about 3.35 GiB of system pagefile use. The largest worker then held roughly 6.04 GiB of private committed memory but only 1.88 GiB resident. The raw memory/process snapshot is local `memory_pressure_snapshot.json`. Sampled RSS is resident RAM, not total allocated/committed memory; the low resident peak must not be interpreted as an algorithmic memory reduction relative to Ubuntu.

The companion restart-preservation process failed with a Windows file-lock error (`WinError 32`) on `restart_checkpoints/step_0.building/field/Bx.npy`, retrying while the solver ran and exiting with code 2. Solver final field saves and CSV timing succeeded, but a preserved restart package was not established. The watcher may have added I/O/memory load; its effect was not isolated. Therefore these timings are observations under memory pressure and a failing background companion, not a clean CPU-only performance baseline or a basis for a guaranteed full-run extrapolation. No claim is made that memory pressure or Windows alone explains the difference from Ubuntu.
